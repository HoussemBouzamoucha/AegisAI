FALSE POSITIVES — Rust Build Artifacts (proc-macro DLLs)
=========================================================

SYMPTOM
-------
Quick/full scan flags legitimate Rust compiler artifacts as MALICIOUS.

Example:
  C:\Users\houss\AppData\Local\Temp\proc-macro-srv2774-0\asn1_rs_derive-0d29ba9264b03c28-141338040437318214.dll
  Score 12 — Behavioral.Malware.Detected — 90% confidence

Detection signals that fired:
  [STRUCTURE]  PE executable                                    +3
  [CONTENT]    Cryptocurrency wallet address detected           +5
  [KEYWORD]    Suspicious keywords: curl                        +3
  [TIMESTAMP]  Timestamp: modified < created (copied file)     +1

ROOT CAUSE
----------
1. Crypto wallet address regex is too broad.
   asn1_rs_derive is a crate for ASN.1/DER parsing (used by TLS libraries:
   rustls, webpki, x509-parser). ASN.1/DER encoded data contains long
   hexadecimal byte sequences that match the wallet address pattern.
   This is a false positive on any cryptography-related DLL.

2. "curl" keyword is too generic.
   curl is a ubiquitous HTTP library name. Flagging it as suspicious
   produces noise on virtually every networked application's build artifacts.

3. Timestamp heuristic fires on all cargo build outputs.
   Cargo creates a temp file then copies/moves the artifact — the
   modified < created pattern is normal for all cargo-built DLLs.

4. No trust rule for proc-macro-srv directories.
   Files under %TEMP%\proc-macro-srv* are always Rust compiler internals
   (proc-macro plugins compiled on-the-fly by cargo). They are never malware.

FIXES (pending)
---------------
1. Trust path: proc-macro-srv directories
   Files matching %TEMP%\proc-macro-srv* should be excluded from scanning
   or capped at Suspicious maximum (never Malicious).
   Implementation: heuristics.rs path_trust_tier() or scan_all.rs skip_dirs.

2. Tighten crypto wallet address detection
   Require the candidate string to be standalone (word-boundary or
   whitespace delimited) and surrounded by low-entropy context.
   Matching inside dense binary data (entropy > 6.5 bits/byte in the
   surrounding 256-byte window) should be suppressed.
   Implementation: Antivirus_Engine/src/core/file_system/heuristics.rs
   check_content() — add entropy-gating around the wallet address regex.

3. Downgrade or remove "curl" as a suspicious keyword
   curl is too generic. Replace with more specific patterns:
   "curl_exec", "curl_easy_setopt" (PHP/C API), or context-gate it
   to script files only (.php, .py, .sh) rather than compiled binaries.
   Implementation: heuristics.rs suspicious keywords list.

AFFECTED FILES
--------------
  Antivirus_Engine/src/core/file_system/heuristics.rs  (wallet regex, curl keyword)
  Antivirus_Engine/src/core/file_system/scan_all.rs    (skip_dirs for proc-macro-srv)
